# Local SQLite Session Cache With Explicit Retention

Prompt Lens will use a local SQLite database as its disposable derived index and cache for Session metadata and full Turn content, loading full Turns only when needed. The original Claude, Codex, OpenCode, Antigravity, and Kiro records remain authoritative. This replaces the JSON spill-file design because SQLite better supports indexed aggregation and bounded lifecycle management; the interface will describe the managed amount as **Cached Content**, not RAM, because it is not a measurement or hard limit of total process memory.

The cache remains local-only, uses safe internal identifiers, and retains full Turn content for up to 30 days within a 250 MB limit, evicting least-recently-accessed content first while preserving Session metadata. It uses restrictive file permissions where supported, stores content as disclosed local plaintext rather than introducing application-managed encryption, and provides a cache-clear command, configurable retention, and an option to disable full-content caching. Existing JSON cache entries are migrated and verified individually before their source files are removed.

Scanning is incremental: Prompt Lens records source identity and change evidence, then reparses only new or changed records. When an authoritative source Session disappears, reconciliation removes both its cached content and metadata; users who need a permanent record must explicitly export an Exported Transcript before deleting the source. Cache diagnostics are available through `prompt-lens cache status` rather than occupying the primary interface. The product does not promise a strict process-memory ceiling; real process memory may be exposed separately as diagnostic information.
